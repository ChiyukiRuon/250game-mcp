# 实现与验证

## 项目结构

```text
src/index.ts       stdio 入口与退出清理
src/server.ts      MCP 工具、资源、模型说明
src/client.ts      WebSocket 生命周期、状态机、确认与等待
src/protocol.ts    类型、输入结构、公开状态白名单
src/rules.ts       移植的上游摆牌/插牌检查
test/             模拟协议测试、MCP 测试、原服务端集成测试
```

游戏服务端与 MCP 是两个独立进程。MCP 使用官方 `@modelcontextprotocol/sdk` 1.x API，工具输入由 Zod 校验；WebSocket 由 `ws` 实现。依赖版本记录在 `package-lock.json`。

参考协议来自 [250game-server](https://github.com/zxy19/250game-server/tree/77372d4202b6344e87697a817a7650fc1182ec21)。`src/rules.ts` 从该提交的 `modules/gameroom/util/game.ts` 移植合法性检查，调整导入、类型和格式；保留 MIT 许可声明。未复制或改动服务端运行入口。

入站牌局立即移除其他玩家手牌、牌堆和任意附加字段。给模型的输出再次使用白名单构造，结算和重连收到的完整快照也遵循同一策略。玩家名称等文本只作为数据返回，不参与指令拼接。

操作分为确认型和无单独确认型。前者等待相关事件，超时后保留未知结果状态，阻止重复提交；后者记录本阶段已响应，等最终事件推进。所有游戏变更携带客户端状态版本，拒绝过期调用。

## 本地验证

```sh
npm ci
npm run build
npm test
npm run format:check
```

原服务端集成测试默认使用相邻目录 `../250game-server`。也可以指定其他副本：

```powershell
$env:GAME_SERVER_SOURCE = 'D:/CodeProject/Project/250game-server'
npm test
```

该源码副本需先执行 `npm ci --ignore-scripts` 安装其依赖。测试导入原始 WSS 和房间管理类，使用随机空闲端口，结束后关闭子进程，不连接线上房间。测试专用进程固定随机数以获得可重复的发牌，不修改原文件。

覆盖内容：

- 完整状态泄露过滤、独立心跳及不干扰版本号。
- 过期版本、非手牌、重复响应被拒绝。
- 多步王牌选择、候选项与数量检查。
- 无响应超时、迟到确认解除暂停。
- 等待超时、取消和断线唤醒。
- MCP 协议工具发现、资源读取、错误返回。
- 实际子进程 stdio 握手与工具调用，确认标准输出未混入日志。
- 未修改的原服务端中，两名玩家加入、准备、摆牌、插牌、抽弃牌、算牌与放弃反算、下一轮、旁观、重连，以及累计超过 250 分后返回大厅。

原服务端源码或依赖缺失时，集成测试会明确标记跳过；模拟协议和 MCP 测试仍运行。测试不包含线上部署、浏览器 UI 或实际模型长时间自主对局验证，也没有穷举所有王牌、反算组合。服务端已有的规则边界与重连缺陷仍然存在。
